# Power BI Data Model — Schema Reference

Star schema: one fact table (`fact_supply_chain`) surrounded by four dimension tables.
All files live in `data/processed/` and are generated by `python/01_data_cleaning.py`.

```
                dim_product
                     │
                     │ product_key
                     ▼
dim_location ──► fact_supply_chain ◄── dim_supplier
   location_key        ▲   supplier_key
                        │
                        │ shipping_key
                        │
                  dim_shipping
```

## dim_product
| Column | Type | Description |
|---|---|---|
| product_key | INT (PK) | Surrogate key |
| sku | TEXT | Product SKU |
| product_type | TEXT | haircare / skincare / cosmetics |
| price | NUMERIC | Unit price |

## dim_supplier
| Column | Type | Description |
|---|---|---|
| supplier_key | INT (PK) | Surrogate key |
| supplier_name | TEXT | Supplier 1–5 |
| location | TEXT | Supplier's city |

## dim_shipping
| Column | Type | Description |
|---|---|---|
| shipping_key | INT (PK) | Surrogate key |
| shipping_carriers | TEXT | Carrier A/B/C |
| transportation_modes | TEXT | Road / Air / Sea / Rail |
| routes | TEXT | Route A/B/C |

## dim_location
| Column | Type | Description |
|---|---|---|
| location_key | INT (PK) | Surrogate key |
| location | TEXT | City (Mumbai, Delhi, Bangalore, Chennai, Kolkata) |

## fact_supply_chain
| Column | Type | Description |
|---|---|---|
| record_id | INT (PK) | Row-level surrogate key |
| product_key / supplier_key / shipping_key / location_key | INT (FK) | Links to dimensions |
| availability | INT | Units available |
| number_of_products_sold | INT | Units sold |
| revenue_generated | NUMERIC | Revenue ($) |
| customer_demographics | TEXT | Buyer segment |
| stock_levels | INT | On-hand inventory |
| lead_times | INT | Order lead time (days) |
| order_quantities | INT | Units ordered |
| shipping_times | INT | Shipping time (days) |
| shipping_costs | NUMERIC | Shipping cost ($) |
| production_volumes | INT | Units produced |
| manufacturing_lead_time | INT | Manufacturing lead time (days) |
| manufacturing_costs | NUMERIC | Manufacturing cost ($) |
| inspection_results | TEXT | Pass / Fail / Pending |
| defect_rates | NUMERIC | Defect rate (%) |
| costs | NUMERIC | Total logistics cost ($) |
| order_fill_rate | NUMERIC | Row-level fill rate (%), capped at 100 |
| inventory_turnover | NUMERIC | Units sold / stock level |
| on_time_delivery_flag | INT (0/1) | 1 if shipping time ≤ median for its mode |
| warehouse_utilization_pct | NUMERIC | Stock / (stock + order qty) × 100 |
| profit | NUMERIC | revenue − costs |
| profit_margin_pct | NUMERIC | profit / revenue × 100 |
| total_shipping_cost | NUMERIC | units sold × shipping cost |
| is_defective_batch | INT (0/1) | 1 if defect rate above dataset median |
| quality_pass_flag | INT (0/1) | 1 if inspection result = Pass |

## Relationship settings in Power BI
All four relationships are **one (dimension) to many (fact)**, **single direction**
(filter flows dim → fact), **active**. This is the default Power BI suggests when you
drag-connect the key columns — no special configuration needed.
